Docs / Self-hosting

Get a server running.

This is the short path. The full documentation lives in the Mycelium repository. For production, read the server notes before exposing the workspace to the internet.

01 / Laptop

Evaluate locally.

Use this path to kick the tires. It installs the core binaries, enrolls the host, and prompts for optional pieces.

# macOS or Linux
curl --proto '=https' --tlsv1.2 -fsS \
  https://raw.githubusercontent.com/mycelium-linux/mycelium/master/install.sh | bash

Then run mycelium doctor and follow the prompts. You can re-run the installer safely.

02 / Server

Make it persistent.

Use a Linux host with systemd. Put a reverse proxy in front of the Mycelium frontdoor, terminate TLS, and back up the workspace volume and database.

  • Ubuntu 24.04 or a current systemd distribution
  • 4 vCPU, 8 GB RAM, 100 GB SSD
  • DNS record pointing at the host
  • Caddy, Traefik, or nginx for TLS
  • Object storage for larger file workspaces

Server checklist

Before you invite the team.

A workspace that holds the business should be boring to operate: TLS, backups, updates, and a way back in.

01

TLS and DNS

Point a hostname at the server, terminate TLS at the proxy, and redirect HTTP to HTTPS. Do not expose the daemon socket to the network.

02

Backups

Back up the workspace database, object storage, and configuration. Test a restore before you need one.

03

Updates

Use the signed release channel and read the changelog. Re-run the installer or follow the package update path.

Need the complete commands, service units, and security notes? Use the repository docs: mycelium-linux/mycelium/docs. For managed hosting, see Pricing.
